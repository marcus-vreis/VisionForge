Escopo: repositório `marcus-vreis/VisionForge` em `development` (d004a38, v0.21.0 + #151/#152), pacote
`visionforge-studio` 0.21.0 no PyPI, site `marcus-vreis.github.io/visionforge-site`, GUI rodando
localmente (porta 8018), governança do GitHub e o rascunho do paper. Tudo medido em 2026-11-09, no

As tasks que saíram desta auditoria estão em [BACKLOG.md](BACKLOG.md), uma issue por task (#154 a #231).

Legenda: **[F]** fato verificado por comando ou arquivo citado · **[I]** inferência · **[R]** recomendação.

## 1. Resumo executivo

O projeto está em estado invulgarmente bom para um software de pesquisa de uma pessoa: suíte de 6650
testes verde com 95% de cobertura, zero erros de mypy/ruff/eslint/tsc, 176 ADRs, CI em Linux+Windows e
Python 3.12/3.13, instalação testada a partir do PyPI, site bilíngue sem link quebrado. Os riscos
reais estão fora do código-fonte: **governança do repositório** (nenhuma branch protegida, Dependabot e
secret scanning desligados), **cadeia de dependências** (177 vulnerabilidades conhecidas no lock Python,
25 no `npm` de produção), **superfície do servidor local** (sem validação de `Host`, sem cabeçalhos de
segurança, `/docs` exposto) e **licenciamento** (ultralytics AGPL-3.0 como dependência obrigatória de
um pacote MIT). O site e o README públicos estão uma release atrás e não mencionam nada do #118
(MLflow, W&B, HF Hub, Zenodo, GitHub, DVC).

## 3. Achados priorizados

### P0 — resolver antes da próxima release

1. **Branches sem proteção e ruleset desligado** [F]. `main` e `development` aceitam push direto e
   force-push; o ruleset `pr-before-merge` (deletion, non_fast_forward, pull_request) está com
   `enforcement: disabled`. Com um único mantenedor o risco é erro humano, não ataque, mas o projeto
   se vende por reprodutibilidade: um `git push --force` acidental apaga a história que o `run.json`
   referencia. [R] Ativar o ruleset em `main` e `development`, exigir CI verde e 0 revisões.
2. **Dependabot e secret scanning desligados** [F]. 177 CVEs conhecidos no lock e ninguém avisa.
   [R] Ligar Dependabot security updates + `dependabot.yml` (pip, npm, github-actions, mensal, agrupado),
   secret scanning e push protection (grátis para repositório público).
3. **Dependências Python vulneráveis** [F]. As que importam para um app local que abre arquivos de
   terceiros: **pillow 12.1.1** (74 avisos; fix ≥ 12.2.0), **onnx 1.20.1** (19; fix 1.21.0),
   **starlette 0.52.1** (10; fix 1.0.1), **aiohttp 3.14.1** (14; fix 3.14.2), **torch 2.7.1** (11).
   [I] Vários são do mesmo bug relatado em IDs múltiplos; ainda assim pillow e onnx leem bytes
   não confiáveis (datasets importados, pesos ONNX). [R] `uv lock --upgrade-package` para pillow,
   onnx, starlette, aiohttp, filelock, urllib3; torch só quando o cu128 acompanhar.
4. **`shadcn` CLI em `dependencies` do frontend** [F]. Puxa hono, @modelcontextprotocol/sdk,
   body-parser, proxy-addr (o único *critical*) para a árvore de produção. Nada disso vai para o
   bundle, mas `npm audit` fica inútil e o install do dev baixa um servidor MCP inteiro. [R] Mover
   `shadcn`, `tailwindcss`, `@tailwindcss/vite`, `@types/js-yaml` para `devDependencies`; `npm audit fix`.
5. **Servidor local sem validação de `Host`** [F]. Qualquer página maliciosa aberta no mesmo
   computador pode fazer DNS rebinding e falar com `127.0.0.1:8000` como se fosse a GUI: as rotas
   de leitura não checam `Origin`, e só duas rotas de `routes.py` (linhas 645 e 687), `folder_opener`
   e o router `/dvc` checam. Os 112 endpoints
   mutantes incluem apagar execuções, gravar tokens e iniciar treinos. [R] `TrustedHostMiddleware`
   com `localhost`, `127.0.0.1`, `[::1]` (+ hostname quando `--host 0.0.0.0`), e um middleware que
   rejeita `Origin` não-loopback em todo método não-GET (hoje isso existe só em três routers).
6. **Sem cabeçalhos de segurança no SPA** [F]. Faltam `Content-Security-Policy`, `X-Frame-Options`,
   `X-Content-Type-Options`, `Referrer-Policy`. Para um app local, CSP é a defesa barata contra
   XSS em nomes de dataset/classe vindos de arquivos importados. [R] Middleware com CSP
   `default-src 'self'` (o SPA não usa CDN), `frame-ancestors 'none'`, `nosniff`.

### P1 — próximas semanas

7. **Licença: ultralytics 8.4.60 + ultralytics-thop 2.0.19 são AGPL-3.0 e obrigatórios** [F]
   (`ultralytics>=8.3` em `dependencies`; ADR-106 tornou obrigatório; `LICENSE` MIT, classifier MIT). [I] Distribuir um

12. **Bundle único de 1 MB sem code splitting** [F]. Cada abertura da GUI baixa tudo, incluindo
    painéis de exportação (Zenodo, GitHub, DVC, W&B, HF) que a maioria nunca abre. [R]

13. **Importar `visionforge.gui.server` leva 5,4 s** [F]; 4,1 s são `visionforge.core.data` →

14. **Sem `SECURITY.md`, `CODE_OF_CONDUCT.md`, PR template, topics** [F] (community profile 57 %).
    [R] SECURITY.md com e-mail e "sem bounty"; topics `computer-vision pytorch reproducibility

15. ~~PyPI sem attestations e classifiers só Linux~~ **Refutado** na verificação: o endpoint de

## 6. Ideias (além de consertos)

### Ganhos rápidos (≤ 1 dia cada)
- `visionforge gui --check`: sobe o servidor, bate em `/api/health`, abre e fecha; vira smoke test do install.
- Badge "versão no PyPI" e "última release" no site lidas da API do PyPI em build time (Astro), para nunca mais ficar atrás.
- `visionforge doctor --json` para colar em issues; o bug_report.yml pede isso automaticamente.
- Página `/docs/changelog` no site gerada do `CHANGELOG.md` no `cd.yml`.
- `SECURITY.md` + `CITATION.cff` já pronto → ativar "Cite this repository" com DOI de versão.

### Apostas maiores
- **Modo "offline garantido"**: flag/perfil que bloqueia qualquer socket não-loopback (monkeypatch em `socket.create_connection`) e prova, com teste, que treinar não toca a rede. É um argumento de paper e um diferencial frente a MLflow/W&B.
- **Verificação independente de resultado**: `visionforge verify-bundle` já checa hashes; o próximo passo é `visionforge reproduce <bundle>` que re-treina 1 seed e compara com o IC do bundle. Fecha o ciclo "resultados que você consegue defender".
- **Catálogo de experimentos em SQLite** em vez de varrer `outputs/` (o `run_history._group_brief` tem CC 21 por isso); habilita busca, comparação cruzada e um `visionforge ls`.
- **Plugin de exportador**: os seis exportadores compartilham `run_report.py`; um entry-point `visionforge.exporters` permitiria a comunidade adicionar o sétimo sem tocar em `routes.py`.
- **Paper**: medir e reportar a variância entre seeds que o próprio projeto reduz (é o resultado central) com `research/seed_variance` público; adicionar uma figura de "tempo até o primeiro treino" comparando com Lightning/Ultralytics CLI.
